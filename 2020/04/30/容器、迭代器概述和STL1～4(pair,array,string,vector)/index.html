容器、迭代器概述和STL1(pair,array,string,vector)

发表于2020-04-30|更新于2025-07-16|基本知识STL
|阅读量:

　　本帖主要讲解STL标准模板库中的pair、array、string和vector，只需要学生学过数组和结构体就可以学习本帖。

一、容器和迭代器概述

1.1 STL和容器分类

　　我们在这里第一次正式地讲解标准模板库(Standard Template Library, STL)。

　　STL包含有大量的模板类和模板函数，是 C++ 提供的一个基础模板的集合，用于完成诸如输入/输出、数学计算等功能。STL 是一些容器、算法和其他一些组件的集合，所有容器和算法都是总结了几十年来算法和数据结构的研究成果，汇集了许多计算机专家学者经验的基础上实现的，因此可以说，STL 基本上达到了各种存储方法和相关算法的高度优化。

　　STL标准库中包含序列式容器、关联式容器、无序关联式容器这三个大类别。

　　１）序列式容器包括 array、vector、deque、list 和 forward_list 容器。其共同的特点是不会自动对存储的元素进行排序，元素排列的顺序取决于存储它们的顺序。数据是无序的！

　　２）关联式容器，包括 map、multimap、set 以及 multiset 这 4 种容器。和序列式容器不同的是，关联式容器在存储元素时还会为每个元素在配备一个键，整体以"键值对"的方式存储到容器中。相比前者，关联式容器可以通过键值直接找到对应的元素，而无需遍历整个容器。另外，关联式容器在存储元素时，默认会根据各元素键值的大小做升序排序。相比其它类型容器，关联式容器查找、访问、插入和删除指定元素的效率更高。

　　３）无序关联式容器，又称哈希容器，主要包含 unordered_set和unordered_map这两种容器。和关联式容器一样，此类容器存储的也是键值对元素。不同之处在于，关联式容器默认情况下会对存储的元素做升序排序，而无序关联式容器不会自动排序。和其它类容器相比，无序关联式容器擅长通过指定键查找对应的值，而遍历容器中存储元素的效率不如关联式容器。

　　容器是一些模板类的集合，封装的是组织数据的方法（也就是数据结构）。

1.2 迭代器（iterator）

　　无论是序列容器还是关联容器，最常做的操作无疑是遍历容器中存储的元素，而实现此操作，多数情况会选用“迭代器（iterator）”来实现。那么，迭代器到底是什么呢？

　　我们知道，尽管不同容器的内部结构各异，但它们本质上都是用来存储大量数据的，换句话说，都是一串能存储多个数据的存储单元。因此，诸如数据的排序、查找、求和等需要对数据进行遍历的操作方法应该是类似的。简单来讲，迭代器和 C++的指针非常类似，它可以是需要的任意类型，通过迭代器可以指向容器中的某个元素，如果需要，还可以对该元素进行读/写操作。

1.2.1 迭代器类别

　　STL标准库为每一种标准容器定义了一种迭代器类型，这意味着，不同容器的迭代器也不同，其功能强弱也有所不同。常用的迭代器按功能强弱分为输入迭代器、输出迭代器、前向迭代器、双向迭代器、随机访问迭代器 5 种。我们重点讲解后面三种。

  1. 前向迭代器（forward iterator） 　　　　假设 p 是一个前向迭代器，则 p 支持 ++p，p++，*p 操作，还可以被复制或赋值，可以用 == 和 != 运算符进行比较。此外，两个正向迭代器可以互相赋值。

  2. 双向迭代器（bidirectional iterator） 　　　　双向迭代器具有正向迭代器的全部功能，除此之外，假设 p 是一个双向迭代器，则还可以进行 --p 或者 p-- 操作（即一次向后移动一个位置）。

  3. 随机访问迭代器（random access iterator） 　　　　随机访问迭代器具有双向迭代器的全部功能。除此之外，假设 p 是一个随机访问迭代器，i 是一个整型变量或常量，则 p 还支持以下操作：

    • p+=i：使得 p 往后移动 i 个元素。

    • p-=i：使得 p 往前移动 i 个元素。

    • p+i：返回 p 后面第 i 个元素的迭代器。

    • p-i：返回 p 前面第 i 个元素的迭代器。

    • p[i]：返回 p 后面第 i 个元素的引用。

    　　此外，两个随机访问迭代器 p1、p2 还可以用 <、>、<=、>= 运算符进行比较。另外，表达式 p2-p1 也是有定义的，其返回值表示 p2 所指向元素和 p1 所指向元素的序号之差（也可以说是 p2 和 p1 之间的元素个数减一）。

    容器 对应的迭代器类型
    array 随机访问迭代器
    vector 随机访问迭代器
    deque 随机访问迭代器
    list 双向迭代器
    set /multiset 双向迭代器
    map / multimap 双向迭代器
    forward_list 前向迭代器
    unordered_map / unordered_multimap 前向迭代器
    unordered_set / unordered_multiset 前向迭代器
    stack 不支持迭代器
    queue 不支持迭代器

1.2.2 定义格式

　　容器类名<参数表>::iterator 迭代器名;

　　这是一般的迭代器的定义格式，注意，参数表内容主要取决于该迭代器使用在哪个容器内，主要用来修饰容器，可能不止一个参数。

　　关于迭代器的具体用法，需要结合具体的容器来体会，所以就在讲解各个容器的时候来展示吧。

二、pair(STL1)

　　在 C++14 中，std::pair 是 STL（标准模板库）的一部分，定义于头文件 <utility> 中，不算是一种容器。它是一个轻量级的模板结构体，用于将两个不同类型的值组合成一个对象，常用于需要返回多个值或简化数据结构的场景。

　　pair不是一个必须掌握的STL。学生如果实在不会，可以使用结构体类型来平替，只不过代码写得稍多一点而已。对同学们的要求是“能读懂，写自愿”，即“必须要能读懂带有pair的代码；至于自己写代码时，可根据自己的实际能力来选择，只要写得又快又准就好”。

　　pair经常可用作优先队列的基本元素。优先队列默认是先出队最大元素，即默认为大顶堆。当pair作为优先队列的元素时，会先自动比较其first成员的大小；在first成员相同的前提下才会去比较second成员的大小。

　　如果希望优先队列先出队最小元素，可以考虑将数值取负数进行存入。

三、array容器(STL2)

　　在 C++14 中，std::array 是标准库提供的固定大小的数组容器，定义于 <array> 头文件。它封装了传统 C 风格数组，提供了类型安全、接口标准化和与 STL 算法兼容的特性。在实际编码时，这个容器用得很少，因为绝大部分学生都更熟悉普通的数组写法（例如int a[10];）。所以对于array容器的学习要求是“能读懂，写自愿”，和pair一样。

3.2 核心特点

  1. 固定大小 std::array 的大小在编译时确定，无法运行时修改，但内存连续分配，性能接近原生数组。

  2. 类型安全 作为模板类，编译器会检查类型一致性，避免隐式类型转换错误。

  3. STL 兼容性 支持迭代器、范围 for 循环和 STL 算法（如 std::sort、std::find）。

  4. 聚合类型 可直接使用聚合初始化，无需显式调用构造函数。

3.3 优点

优点 说明
安全性 提供边界检查（at()），避免越界未定义行为
接口丰富 支持 front()、back()、fill() 等成员函数，操作直观
性能高效 内存连续，缓存友好；无动态内存分配开销
与 C 互操作 通过 data() 获取原生指针，兼容 C 风格 API
现代特性支持 支持 C++11 的初始化列表、C++14 的泛型 lambda 等

3.4 缺点

缺点 说明
固定大小 无法动态扩容或缩容，需预先确定大小
默认初始化风险 未显式初始化时，内置类型元素为未定义值（需手动初始化）
不支持动态分配 无法像 std::vector 通过 reserve() 预分配内存
多维数组限制 多维数组需嵌套定义（如 array<array<int, 3>, 2>），灵活性较低

3.5 适用场景

  1. 固定大小数据存储 如数学中的向量、矩阵，或需要频繁访问的配置参数。

  2. 与 C 接口交互 通过 data() 传递给需要原生数组的 C 函数。

  3. 替代原生数组 在需要类型安全和 STL 兼容性的场景下替代 T[N]。

  4. 性能敏感场景 内存连续且无动态分配开销，适合嵌入式或实时系统。

3.6 与原生数组的对比

内存管理 自动管理（栈分配） 需手动管理（可能堆分配）

3.8 总结

　　std::array 是 C++ 中处理固定大小数组的最佳实践，兼顾了安全性与性能。尽管无法动态调整大小，但其标准化接口和与 STL 的无缝集成使其在需要固定内存布局的场景中不可替代。对于需要动态扩展的场景，应选择 std::vector。

四、string容器(STL3)

　　在 C++14 中，std::string 是标准模板库（STL）中专门用于处理字符序列的容器，属于 序列容器，定义于 <string> 头文件。它封装了动态字符数组的管理。建议在刷完C++基础部分的内容之后再来学string，将"字符数组"这部分的个别题用string来实现。

4.1 核心特性

4.1.1 序列容器属性

  • 顺序存储：字符按顺序存储在连续内存中，支持随机访问。
  • 动态扩展：自动管理内存，支持动态增减字符（如 push_back、resize）。
  • 固定字符类型：特化为 char 类型（std::basic_string<char> 的别名）。

4.1.2 与 C 风格字符串的对比

特性 std::string C 风格字符串（char*）

安全性 边界检查（at()），防止越界 无保护，易引发缓冲区溢出
功能丰富性 提供 find、substr 等成员函数 依赖外部函数（如 strlen）

4.3 string和char[]的相互转换

4.3.1 适用场合区分

1）char[]数组在初学时更常见，学生习惯性使用得更多。因为它是字符数组的底层原始实现，所以更加精细，代码也更加繁琐。如果题目中对字符数据的处理需要逐个字符地进行，那么用char[]来做是比较方便的。但char[]对应的一套函数中，并没有现成的插入、删除、函数，需要自己手工去实现，判等的写法也较为冗长，较为麻烦，不适合需要频繁插入、删除的情况，或者说写起来代码量较大。

五、vector容器(STL4)

　　在 C++14 中，std::vector 是标准模板库（STL）中最常用的动态数组容器，支持高效随机访问和动态扩容。　　vector在竞赛中较多地使用在图或树的邻接表中，偶尔会用于一些变长数组的处理。一般不用于字符串。

5.3 扩容机制

  • 动态扩容：当 size() == capacity() 时，push_back 会分配更大的内存（通常扩容为原容量的 1.5~2 倍），并将原有元素拷贝到新内存。
  • 预分配优化：使用 reserve(n) 提前分配足够内存，避免频繁扩容带来的性能损耗。

5.4 与其他容器的对比

容器 特点 适用场景
std::vector 动态数组，连续内存，支持随机访问，尾部操作高效 需要频繁随机访问的动态数据集合
std::list 双向链表，插入/删除高效（任意位置 O(1)），不支持随机访问 频繁中间插入/删除的场景
std::array 固定大小数组，栈分配，无动态扩容 大小已知的静态数据

　　vector和array的区别在于，vector可以不用指定其数据规模，遇到装不下时系统会自动为其扩容。vector可用于数据规模不太明确的场合，例如存储每个结点的邻接点（邻接表）。
