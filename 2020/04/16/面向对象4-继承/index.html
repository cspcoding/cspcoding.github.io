面向对象４-继承

一、为什么我们需要继承

　　回想一下以前学函数的时候，为什么我们需要自己定义函数？因为可以把一些相同的代码装到一个自定义的函数里，使用时只需要调用该函数就可以了。这样就大量节省了代码。那这种方法或者基本思想，能不能用在这里呢？基本思想肯定是没问题的。我们仔细观察一下诸多职业类中的相同代码，会发现这些代码之所以相同，是因为它们都是作为一个人的基本属性或者动作方法，而不是作为一个职业的专有属性或方法。那么我们可以定义一个独立的基本的类，把这些相同的属性或方法放到这个基本的类里面，然后想办法让这个基本的类和我们需要定义的职业类之间产生某种关系，就可以达到简化代码的目的了。面向对象的机制，于是就诞生了“继承”这个技术。

　　继承允许新类（派生类）基于已有类（基类）复用代码，并扩展或修改功能。

二、继承的基本写法

　　在C＋＋中，如果多个类都具有一些相同的属性和方法，将这些内容都抽取到一个单独的类中，那么这多个类就不需再定义这些属性和方法，只需要继承这个单独的类就可以了。继承的基本写法格式如下：

　　子类继承了父类，所以子类自动具有父类的成员变量和成员方法（构造方法、析构方法、私有成员都无法继承）。子类又叫做派生类，父类又叫做基类，或叫超类。派生类是基类的一种特殊类型（"is-a" 关系）。例如：Dog类 是 Animal类 的一种。

　　访问控制修饰符用于控制基类成员在派生类中的访问权限。

  • public（常用）继承：基类／父类的公有成员在派生类／子类中仍然是公有的，保护成员仍然是保护的 。也就是说，继承后，父类的所有成员的权限维持不变。类似于“儿子继承王位后，维持父皇生前的对内和对外政策不变”。

  • protected继承：基类／父类的公有和保护成员在派生类／子类中都变为保护的。

  • private继承：基类／父类的公有和保护成员在派生类／子类中都变为私有的（默认继承方式）。也就是说，继承后，父类的所有成员的权限都成为私有的，只能在父类或子类中使用，不允许外人／外类使用。类似于“儿子继承王位后，把父皇生前的所有对外政策都禁止，只准国内使用”。

    继承方式 基类 public 成员在派生类中的权限 基类 protected 成员在派生类中的权限 基类 private 成员在派生类中的权限
    public public protected 不可访问
    protected protected protected 不可访问

三、继承的优缺点

3.1 优点

  • 提高了代码的重用性。这一点很好理解，我们定义一个Person类，后续所有的职业类都可以少写很多代码．

  • 提高了代码的维护性。当我们需要修改eat()或者setname()等Person类的函数代码时，如果采用以前的方法，因为每个类都写了相同的eat或setname函数，现在要改就得对每个职业类的这些函数都要改一遍，非常麻烦，容易出错。但如果只有一份代码（通过继承的方式，只需父类这一份代码），修改起来就很方便了。

  • 让类和类之间产生了关系，为后续的“多态”提供了前提基础

3.2 缺点

　　软件开发的基本设计原则是“低耦合，高内聚”。

  • “耦合”的意思是模块之间的关联或关系。“低耦合”的意思是指模块和模块之间要尽量少关联，尽可能独立不相关。否则可能“牵一发而动全身（这是典型的高耦合，很不好）”，容易造成混乱。就好象一个人的学习好，并不依赖于周围同学朋友的学习情况，也不依赖于学校或老师的能力。
  • “内聚”的意思是模块自己独立完成一个或一些功能的能力。“高内聚”的意思是指模块完成某个功能的代码都集中在这里了，只要执行了就能完成功能，无需借助其他任何外来信息或其他模块。就好象一个人，通过自学就能达到学习优异。

　　“低耦合，高内聚”的意思，基本上可以比喻为一个学生，不依赖于任何的外部环境或要素，只靠自己就能优秀地完成学习任务。可以随意地驱使来去，没有任何的依赖或后遗症，又能优秀地完成任务。

　　继承，是增强了类和类之间的耦合性的，但这却是它的缺点。这也很好理解。一个学生类的所有成员，其中一大部分成员的定义都在Person类中，也就是在学生类以外的其他类中。万一这个类的定义出现了某些修改，而Student类假如不想有这些修改，行不行呢？肯定是不行的。你既然继承了父亲的资产，同时肯定也会继承父亲的债务。某些你认为不需要的成员变量或者成员方法，还必须得继承给你。

　　再打个比方，我们用“购买”来比喻继承，用“自研自造”来比喻“自己写所有代码”。我们知道联想电脑的所有配件，其实都不是它自己生产制造的，而是从国外的很多厂商购买产品而得，自己只做了个组装而已。这就好比一个类的所有成员和方法，都没有在自己类中定义，全都来自于其他多个类的继承，自己只是写个空壳，把它们封装和继承起来了而已。这样的做法，一旦其他类的定义发生变化（例如国外的厂商要征收高额关税，或者供货质量下降），就会给企业带来经营困难。　　

四、构造函数和析构函数的调用顺序

  • 构造顺序：先调用基类构造函数，再执行派生类构造函数。首先按基类声明顺序（从左到右）依次调用基类的构造函数，再调用派生类自身的构造函数。基类的构造函数总是先于派生类执行，无论派生类如何定义。
  • 析构顺序：先执行派生类析构函数，再调用基类析构函数。

　　在派生类构造函数执行时，默认会调用基类的无参构造函数（前提是基类要有无参构造函数）。当然，也可以显式调用基类的其他构造函数。如下代码所示：

5.4 方法重写

5.4.1 方法重载(Overload)、方法隐藏(Hide)　和　方法重写(Override)

  • 方法重载(Overload)：本类中出现了多个“方法名称完全相同，形参表不同（个数，顺序，类型等有任何一个不相同都算）”的方法，这种叫方法重载。方法重载不看方法的返回类型。
  • 方法隐藏(Hide)：子类中出现了和父类中的方法的名字都相同，不管参数表和返回类型是否相同。
  • 方法重写(Override)：子类中出现了和父类中的方法声明（方法名称、形参表、返回值类型）一模一样的方法（须用override 修饰），并且基类的该方法须用virtual修饰（即是虚函数）。又称为“方法覆盖”或“方法复写”。

区别点如下：

  • 方法名称：方法重载指的是同一个类中的方法同名；方法隐藏和方法重写都是指父类和子类之间的同名；
  • 返回值类型：方法重载和方法隐藏都不考虑返回值类型；而方法重写要考虑返回值类型，若返回值类型不相同，不认为是方法重写，会认为是一个不同的方法。
  • 形参表：方法重载要求形参表必须不相同，否则会认为是重复定义；方法隐藏不看形参表，相同或不同都无所谓；方法重写要求形参表必须相同。
  • 多态性：仅只有方法重写支持多态性，即在运行时去匹配需要调用的是哪个方法。

六、多继承

　　C++ 支持多继承 （Multiple Inheritance），即一个类可以同时继承多个基类。这种特性使得 C++ 的继承机制比一些其他语言（如 Java）更加灵活，但也带来了复杂性和潜在的问题。、

6.2 多继承的优点

  • 代码复用性增强 ：子类可以同时继承多个父类的功能。

  • 灵活性高：能够更好地模拟现实世界中的复杂关系。

  • 接口实现 ：通过多继承，可以实现类似于接口（你可以理解为某种只有方法而没有成员的类）的功能（例如，继承多个抽象类）。

6.3 多继承的缺点

　　尽管多继承功能强大，但它也产生了一些问题：

  1. 二义性问题 ：如果多个基类中有同名的成员，派生类在访问这些成员时会产生歧义。在上一节中我们展示的代码里就有二义性的问题，关于name变量。下面再看一个具有二义性的代码：

  2. 菱形继承问题 ：当多个基类继承自同一个父类时，根据这些基类去派生出一个子类时，会导致重复继承的问题。（你可以理解为近亲结婚，生出来了怪胎）解决方案是使用虚继承 （virtual inheritance）来确保在D的对象的内存中只有一个 A 对象的相关所有变量的内存。

  3. 复杂性增加 ：多继承的设计和维护成本较高，容易引发难以调试的错误。

6.4 关于“多继承”的忠告

  • 尽量避免多继承 ：如果可能，优先使用单继承来代替多继承。

  • 使用接口式多继承 ：将基类设计为纯抽象类（只包含纯虚函数），以实现类似接口的功能。

  • 解决二义性问题 ：明确指定调用的基类成员。

  • 使用虚继承 ：解决菱形继承问题。
