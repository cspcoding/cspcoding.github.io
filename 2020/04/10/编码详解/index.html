编码详解

发表于2020-04-10|更新于2025-04-12|基本知识
|阅读量:

一、现代编码模型

　　在现代编码模型里要知道一个字符如何映射成计算机里比特，需要经过如下几个步骤：

　　１．知道一个系统需要支持哪些字符，这些字符的集合被称为字符表（Character repertoire）。

　　２．给字符表里的抽象字符编上一个数字，也就是字符集合到一个整数集合的映射。这种映射称为编码字符集（CCS：Coded Character Set）。Unicode编码就是属于这一层的概念，跟计算机里的什么进制啊，比特等没有任何关系，它是完全数学的抽象的。常见的字符集有ASCII字符集、GBK字符集(主要用于处理中文汉字)、Unicode字符集等。

　　３．将 CCS 里字符对应的整数转换成有限长度的比特值，便于以后计算机使用一定长度的二进制形式表示该整数。这个对应关系被称为字符编码表（CEF：Character Encoding Form）。UTF-8、 UTF-16等都属于这层。

　　４．对于 CEF 得到的比特值具体如何在计算机中进行存储，传输。因为存在大端／小端的问题，这就会跟具体的操作系统相关了。这种解决方案称为字符编码方案（CES：Character Encoding Scheme）。

　　平常我们所说的编码都在第三步的时候完成了，都没有涉及到 CES。所以 CES 并不在本文的讨论范围之内。

二、编码发展史

2.1 ASCII编码

　　我们知道在计算机中，所有的信息最终都表示为一个二进制的字符串，每一个二进制位有 0 和 1 两种状态，通过不同的排列组合，使用 0 和 1 就可以表示世界上所有的东西。而 1个字节对应 8 位二进制数，每位二进制数有 0、1 两种状态，因此 1 字节可以组合出 256 种状态。如果这 256 中状态每一个都对应一个符号，就能通过 1 字节的数据表示 256 个字符。

　　１９６３年，美国人于是就制定了“美国信息交换标准码”（American Standard Code for Information Interchange，　ASCII， /ˈæski/　）编码，描述英语中的字符和这 8 位二进制数的对应关系，简称为 ASCII 码。早期的ASCII 码（也叫基础ASCII码）一共定义了 128 个字符，包括英文字母字符'A'～'Z'，'a'～'z'，数字字符 '0'～'9'，一些英文标点符号字符和控制符号（不可见）等。这 128 个字符只使用了 8 位二进制数中的后面 7 位，左侧最高的那一位统一规定为 0。码点范围在\(0 \sim 127\)。完整的ASCII码表的内容请看这里。

　　C++中的char类型的字符常量，在内存中占１个字节，存储的就是该字符常量对应的ASCII码整数值。简单的说，就是字符常量在内存中实际上存储的是个整数（肯定是非负的）。

　　这个ASCII码表，同学们可以大概看看，不需要全背，但尽量知道其中一些常用的字符的ASCII码值。空字符（０），字符常量'A'（65, 0B0100 0001, 0X41, \101），字符常量'a'（97, 0B0110 0001, 0x61, \141），空格字符' '（32, 0B0010 0000, 0x20, \40, =97-65, ='a'-'A'），字符'0'（48, 0B0011 0000, 0x30, \60）。

　　一些常用的写法技巧需要知道：

  1. 其他字母码值的推算，例如'D'的ASCII码值为'A'+3；

  2. 假设某个码值为x的大写字母，若要转成对应的小写字母，代码应写为x= x + ' ';，或者说x = x - 'A' + 'a';

  3. 假设某个码值为x的小写字母，若要转成对应的大写字母，代码应写为x= x - ' ';，或者说x = x - 'a' + 'A';

    用反斜杠来做转义字符的标志，常见的转义字符如下：

    ａ）功能转义字符：'\n'（回车键）、'\t'（制表符）

    ｂ）以'\'开头，后跟一个字符，这种写法就表示该字符常量。例如'\\'（反斜杠字符）、'\C'（字符C）、'\''（单引号字符）、

    ｃ）以'\'开头，后跟一个整数，表示用八进制来表示这个字符的ASCII码。例如'\101'（'\'标志着八进制数的开始，\(101_8=65_{10}\)，所以'\101'表示字符常量'A'），'\141'（'\'标志着八进制数的开始，\(141_8=97_{10}\)，所以'\141'表示字符常量'a'），'\141'（'\'标志着八进制数的开始，\(141_8=97_{10}\)，所以'\141'表示字符常量'a'）。需要注意的是，必须要加上一对单引号，内含八进制数。如果没有单引号，是错误的。例如char ch=\101; //语法报错！，但如果是给一个字符变量赋予其他进制数的ASCII码值，则不需要加单引号，例如char c1=65, c2=0x41, c3=0b01000001;。请看下面的代码：

    　　基础ASCII码只定义了１２８个字符，这意味着如果其他非英语国家如果想使用计算机，将无法表示本国的文字。所以后来各个国家分别制定了自己国家的字符编码，例如中国的GB2312（１９８０年实施）、中国台湾地区的Big５、日本的Shift_JIS、韩国的EUC-KR编码等。

    　　但这会带来新的问题。例如在我国境内编写一个文件，用GB2312编码表示汉字“中”，内容是0xD6D0，需2个字节。但是如果把这个文件发给小鬼子，他们收到后，尝试用Shift_JIS编码来解读0xD6D0这个二进制串，结果不忍直视，完全乱码。所以不同编码的文件之间无法直接互通。

2.2 Unicode统一字符集

2.2.1 核心概念

　　1987年启动的Unicode项目提出统一字符集 理念：

  • 为全球所有字符分配唯一的码点（Code Point）。所谓的码点，其实就是一个整数值，和各种进制无关，和具体实现无关，码点的写法格式是“U+XXXX”，其中"XXXX"是一个十六进制表示的整数值。例如：

    • 'A'的码点为U+0041，仍然是十进制的６５，和ASCII码里规定的字符'A'一致，保持了对其的兼容性。
    • "中"的码点为U+4E2D

  • 码点采用十六进制表示，范围从U+0000到U+10FFFF

2.2.2 编码方案

　　针对某一个码点（整数值），如何把它翻译／转换成一个二进制的０／１序列，这是需要解决的第二个问题。

　　Unicode主要有UTF-8、UTF-16和UTF-32这几种编码方案。UTF的全称是：Unicode Transformation Format，表示“Unicode码转换格式”。其中8／16／32分别表示8位(1字节)／16位(2字节)／32位(4字节)，表示一个字符进行编码所需的最小字节单元，也称编码单元，简称码元。这些编码方案根据码点来得到实际存储的码元信息。

三、主流编码方案详解

3.1 UTF-8编码方案

3.1.1 如何编码

　　UTF-8编码是一种变长编码。也就是说，对于不同的码点，其对应的码元长度可能是不一样的。

　　编码规则如下表所示：

序号 字节结构（x表示可为0/1，８bit为１Byte） 码点范围（有漏段） 能表示的最大bit位数（x的个数）
１ 0xxxxxxx U+0000～007F 7
２ 110xxxxx　10xxxxxx U+0080～07FF 11
３ 1110xxxx　10xxxxxx　10xxxxxx U+0800～FFFF 16
４ 11110xxx　10xxxxxx　10xxxxxx　10xxxxxx U+10000～10FFFF 21

例１：已知文字“严”的码点值是 U+4E25，求其UTF-8编码值（十六进制形式）：

解答：

　　１）根据"严" 的码点整数值4E25，其二进制是：100 1110 0010 0101，一共有１５个bit（不含前导０）；

　　２）根据上面的表格的“最大bit位数”所示，15个bit需要用３个字节来表示（\(11<15<16\)），将其补全成\(16\)位的二进制串，并按照“\(4-6-6\)”的长度来分割，分割结果是：0100 111000 100101，可以看到，这个内容分为了３段；

　　３）把这个分割结果串，补全每段左侧的固定头部，最终的UTF-8编码二进制串值是：11100100　10111000　10100101，再把这２４个bit的二进制串转成１６进制，结果就是0xE4 B8 A5，这就是最终答案。

例２：已知字符'A'的码点值是 U+0041，求其UTF-8编码值（十六进制形式）：

解答：

　　１）根据'A' 的码点整数值0041，其二进制是：100 0001，一共有７个bit（不含前导０）；

　　２）根据上面的表格的“最大bit位数”所示，７个bit需要用１个字节来表示（\(7\leq 7<11\)），正好７位，不需补全，也不需要分割（只有一个字节），分割结果串是：100 0001，可以看到，这个内容只有１段；

　　３）把这个分割结果串，补全每段左侧的固定头部“0”，最终的UTF-8编码二进制串值是：0100　0001，再把这８个bit的二进制串转成１６进制，结果是0x41，这就是最终答案。

　　可以看到，最终的UTF-8编码和字符'A'的ASCII码是一样的，并无任何变化。也就是说，UTF-8编码对ASCII编码是完全兼容的，可以用UTF-8编码来解读和打开以前那些纯由ASCII编码生成的文件。

例３：已知字符“😂”的码点值是 U+1F602，求其UTF-8编码值（十六进制形式）：

解答：

　　１）根据"严" 的码点整数值1F602，其二进制是：1 1111 0110 0000 0010，一共有１７个bit（不含前导０）；

　　２）根据上面的表格的“最大bit位数”所示，１７个bit需要用３个字节来表示（\(16<17<21\)），将其补全成\(21\)位的二进制串，并按照“\(3-6-6-6\)”的长度来分割，分割结果是：000 011111 011000 000010，可以看到，这个内容分为了４段；

　　３）把这个分割结果串，补全每段左侧的固定头部，最终的UTF-8编码二进制串值是：11110000　10011111　10011000　10000010，再把这３２个bit的二进制串转成１６进制，结果就是0xF0 9F 98 82，这就是最终答案。

例４：在电脑端接收到从网络中传输过来的某一个字符的UTF-8编码信息，一共有３个字节，内容依次是0xAD B8 E4，这个字符的UTF-8编码值是什么？

解答：

　　这三个字节，第一个字节的高位是'A'，即1010，这并不是一个合法的UTF-8编码的高位。遇到这种问题，应该再看看最后一个字节0xE4的高４位'E'，即1110，这可能是一个合法的UTF-8编码开头。它有３个1，说明完整编码值一共有３个字节（和现实吻合）；之所以这个0xE4排在第三个，可能是因为电脑端用小端系统（低位字节存储在低地址，目前主流操作系统和设备都是小端系统）来接收了这个字节序列，所以该字符正确的UTF-8编码值应该是这个结果的反序，即0xE4 B8 AD。检验一下B8 AD这两个字节的高4位bit，都在'8'到'B'之间，即都在0b1000~0b1011之间，故0xE4 B8 AD是一个正确合法的UTF-8编码值。

　　从例４可以看出，UTF-8编码能够被接收系统自动识别接收顺序，并不会引起任何歧义。

3.1.2 变长编码的判断方法

　　通过首字节的前导1数量 确定字符长度：

  • 0xxxxxxx → 1字节

  • 110xxxxx → 2字节

  • 1110xxxx → 3字节

  • 11110xxx → 4字节

　　后续字节均以10xxxxxx开头，确保解码时能正确分割字节边界。

3.1.3 解码过程

　　UTF-8编码中的前缀码起到了很好的区分和标识的作用，其编码的解析过程大致如下：

  1. 当解码程序读取到一个字节的首位为０，表示这是一个单字节编码的ASCII字符；
  2. 当读取到一个字节的首位为１，表示这是一个非ASCII字符的多字节编码字符中的某个字节（可能是首字节，也可能是后续字节），接下来若继续读取到第二个１，则可以确定当前字节为首字节，再继续读取直到遇见终结标志（即0）为止。一共连续读取了几个1，就表示该字符为几个字节的编码；
  3. 当读取到某一个字节的最左两位为１０，则该字节显然是非ASCII字符的后续字节(即非首字节)。

　　在UTF-8编码方式中，绝大部分的中文用三个字节编码，部分中文用四个字节编码，

3.1.4 核心优势

  1. 完全兼容ASCII码：单字节字符与ASCII完全一致，无需转换。
  2. 节省存储空间 ：常用字符（如拉丁字母、汉字）使用1-3字节，仅生僻字符需4字节。
  3. 无字节序问题 ：UTF-8编码的首字节有独特的前缀码，能被计算机自行判断出谁是首字节，故不存在小端序和大端序造成的歧义情况。

　　UTF-8通过动态调整字节数，平衡了兼容性与效率，成为互联网和操作系统（如Linux）的主流编码方案。

3.2 UTF-16编码方案

　　UTF-16也是一种变长编码，对于一个Unicode字符被编码成1至2个码元，每个码元为2个字节(16位)。也就是说，用UTF-16编码后的１个字符，可能占２个字节或者４个字节。UTF-16编码会有字节序的问题（因为需要确定一个码元内的２个字节，谁摆前谁摆后），所以根据大小端又分为大端UTF-16(UTF-16 BE)和小端UTF-16(UTF-16 LE)。

　　在基本多语言平面内的UTF-16编码使用1个码元，且其值与Unicode是相等的（不需要转换）。举例如下：

Unicode 字符 UTF-16（码元） UTF-16 LE（字节） UTF-16 BE（字节）
U+0041 A 0x0041 0x41 0x00 0x00 0x41
U+03A9 Ω 0x03A9 0xA9 0x03 0x03 0xA9
U+6653 晓 0x6653 0x53 0x66 0x66 0x53

　　码点范围在U+10000-U+10FFFF的编码的详细过程比较复杂，就不在这里详述了，超纲了。同学们只需要知道这个范围的字符，是需要２个码元，４个字节来表示的。假设一个码点为U+2A6A5的字符𪚥，它对应的两个码元分别是0xD869 和0xDEA5（转换过程略），小端序编码结果是0x69 0xD8 0xA5 0xDE，大端序编码结果是0xD8 0x69 0xDE 0xA5。

3.3 UTF-32编码方案

　　UTF-32是一种定长编码，使用１个３２bit的码元，其值与Unicode编码值相等。举例如下:

Unicode（码点） 字符 UTF-32（码元） UTF-32 LE（字节） UTF-32 BE（字节）
U+0041 A 0x00000041 0x41 0x00 0x00 0x00 0x00 0x00 0x00 0x41
U+03A9 Ω 0x000003A9 0xA9 0x03 0x00 0x00 0x00 0x00 0x03 0xA9
U+6653 晓 0x00006653 0x53 0x66 0x00 0x00 0x00 0x00 0x66 0x53
U+2A6A5 𪚥 0x0002A6A5 0xA5 0xA6 0x02 0x00 0x00 0x02 0xA6 0xA5

　　UTF-32同样有大小端的问题，目前用得少。

优缺点：

  • 优点：是定长编码，提取、截断和翻译字符都容易进行。
  • 缺点：浪费存储空间；存在字节序的问题。
